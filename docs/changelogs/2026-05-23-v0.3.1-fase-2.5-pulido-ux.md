# Fase 2.5 — Pulido y UX (v0.3.1)

**Released:** 2026-05-23

## Summary

Ciclo de ~5 semanas dedicado a feedback de beta testers (FB-001 a FB-110+) y refinamiento. La fase no introduce nuevos pilares — afina lo que ya hay: sesiones multi-dispositivo con cookies HttpOnly, módulo `queue` (rename de wishlist), variantes de juego y compilations para datos consolidados de RAWG, búsqueda tolerante a tildes, paginación y stats en endpoints calientes, filtros admin granulares, theme persistido por usuario, security hardening (xss-sanitizer, CORS, JWT TTL más corto), Husky + lint-staged y las primeras Claude skills (`commit`, `endpoint-doc`, `db-migration`). Cierra ~80 FBs.

## Highlights

- Auth multi-sesión: refresh token con `deviceInfo`/`lastUsedAt`, HttpOnly cookie, claim `sid` para tracking de actividad por sesión.
- Variantes de juego y compilations: `variant` por sibling con mismo `rawgId`, `POST /games/:id/split`, `CompilationItem` model + `PUT/DELETE /games/:id/compilation-items`.
- Búsqueda tolerante: token-AND con normalización, accent-insensitive vía `unaccent`, `sort_by=random` para discover.
- Filtros admin: `no_score_source`, `no_time_source`, `is_compilation`, `exclude_compilations`, `include_inactive`/`only_inactive`, filtros por genre/platform/year/score/duration.
- Ratio escalado a 0-100, normalización de scores list-item a escala 5.
- Tema visual persistido por usuario con validación premium (catálogo: `midnight-cyan` añadido).
- Stats endpoint para sidebars (`/backlog/stats`), feed/collections paginados, `/lists/official`, `/lists/recent`, `/games/latest-reviewed`.
- Security hardening: XSS sanitizer, CORS validation, access token a 15m, admin routes con 404 para no-admin, vulnerabilidades npm patcheadas.
- Skills: Husky + lint-staged + skills `commit`, `endpoint-doc`, `db-migration`.

## Added

- **Compilation items:** modelo `CompilationItem` + endpoints `PUT/DELETE /games/:id/compilation-items` con modos link y create, `isCompilation`, `compilationItems`, `partOfCompilations` en serializer.
- **Variants:** columna `variant` en `Game`, siblings con mismo `rawgId` permitidos en `GameExternal`, label requerido. `POST /games/:id/split` para separar registros consolidados.
- **Queue (`queue/`):** rename de `wishlist`, valida que solo entren backlogs en `not_started`, remueve automáticamente al pasar a `playing/completed/abandoned`.
- **Wishlist game-based:** módulo nuevo `wishlist` que apunta a `Game` (no a Backlog), con activity recording al añadir y tracking de plataforma.
- **Stats endpoint:** `GET /users/me/backlog/stats` con conteos agrupados para sidebars.
- **Lists discovery:** `/lists/official`, `/lists/recent` con `firstItem` (cover preview), `/games/latest-reviewed`.
- **Users discovery:** `/users/discover`, search por `q`/`email`, lazy-load de tabs de perfil.
- **Theme persistence:** columna `theme` en `User`, validación de tier premium, catálogo (`midnight-cyan` registrado).
- **Privacy flags granulares:** `isBacklogPublic`, `isShelfPublic`, `isListPublic` en User.
- **Search por unaccent:** PG extension, búsqueda accent-insensitive en title.
- **Random sort:** `sort_by=random` para discover real.
- **Skills (`.claude/skills/`):** `commit`, `endpoint-doc`, `db-migration`. Husky pre-commit con lint-staged.
- **`well-known/` como router:** `robots.txt` y `security.txt` expuestos como rutas.

## Changed

- **Wishlist → Queue rename:** el módulo apuntando a `Backlog` ahora se llama `queue`. La wishlist apuntando a `Game` nace nueva con ese nombre.
- **Ratio escalado a 0-100:** scores normalizados a escala 5, list-items ajustados.
- **Refresh token con `sid`:** tracking de actividad por sesión vía claim JWT.
- **Cookie-based auth:** refresh token en HttpOnly cookie en vez de body.
- **Rate limit subido a 300/min** + exención para admin/moderator.
- **Backlog sort:** `NULLS LAST` para columnas nullable, sort por title/ratio/personalRatio en backend.
- **Compilation context persistido:** `compilationGameId` en backlog con validación de child link.
- **Reviews:** solo cuentan las que tienen contenido no-vacío, exposición de `playthroughDuration` del autor.
- **Lists:** `realDuration` y `personalRatio` por item, sticky-best status priority.
- **Game-reports:** categoría enum para reportes tipados.
- **Default DB name:** `completr` en migrations config.
- **Admin filters:** `include_inactive`/`only_inactive` en `/games`, audit logs con filtros y resolución de target.

## Fixed

- **`game-shelf` total inflado** por join con genres (FB-105) — usar `distinct count`.
- **Backlog `notes`** excluidas de respuestas públicas.
- **Backlog activity** solo se registra cuando el status cambia realmente.
- **Lists progress:** abandoned cuenta como progreso de lista.
- **List-items:** normalized scores redondeados a 2 decimales para evitar artifacts de IEEE 754.
- **Server:** xss sanitizer removido (corrompía text fields con HTML entities).
- **Middleware:** guard contra `request.locals` undefined al mergear schema data.
- **Wishlist ratio** escalado por 20 para matchear otros serializers.
- **Rate-limit middleware** tipa `request.locals.user` como `RequestUser`.
- **Security hardening:** XSS sanitizer middleware, CORS origin validation, JWT TTL 24h → 15m, admin routes con 404 para no-admin.
- **CORS wildcard origin** manejado correctamente en validación.
- **Deps:** sanitize-html override para CVE, 12 vulnerabilidades resueltas vía `npm audit fix`.

## Migration

- Rename `wishlist` → `queue` para el módulo apuntando a `Backlog`. Si tienes código consumiendo el viejo nombre, migrar a `queue`. La nueva `wishlist` apunta a `Game` con semántica distinta.
