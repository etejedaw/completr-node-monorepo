# Phase 0 — Setup and base architecture (v0.1.0)

**Released:** 2026-04-04

## Summary

First backend release. Stands up the entire infrastructure so the following phases can iterate on product without fighting the plumbing: modular structure, three-layer error system, Zod-based validation, JWT authentication, logger with per-request traceability and a game catalog queryable against RAWG. No real users yet — the goal is to leave the architecture solid.

## Highlights

- Project skeleton: TypeScript, Express 5, Sequelize 6, Docker Compose, Postgres + Postgres-test.
- Three-layer error system (`ServiceError` → `DomainError` → `HttpError`) with global normalizers and per-module mappers.
- Full auth with JWT + bcrypt, roles (`user`, `premium`, `moderator`, `admin`) and differentiated rate limiting.
- Catalog modules: `games`, `platforms`, `genres`, `game-platform`, `game-genre`, `game-shelf`.
- Three-tier scoring system: `GameScore`/`GameTime` (global per source), `GameShelf` (per user), `ListItem` (frozen inside lists).
- RAWG provider with `searchGame`, `getGameById`, `getGameBySlug` and filters.
- Config split across `environment.config.ts`, `database.config.ts`, `api-keys.config.ts`.

## Added

- **Auth (`auth/`):** registration, login, JWT, middleware with role verification, password service with bcrypt.
- **Users (`users/`):** model with roles, profile, account management.
- **Games + catalog:** `games`, `platforms`, `genres` with their `game-platform` and `game-genre` pivot tables. Slugs auto-generated from the title.
- **Game shelf:** personal library module with relations to Game and Platform.
- **GameScore + GameTime:** separate tables for scores (Metacritic, OpenCritic, RAWG, Completr) and durations (HLTB, RAWG, Completr).
- **DLC support:** `isDlc`, `parentGameId` and self-reference on `Game`.
- **RAWG provider (`rawg/`):** `RawgProvider` class with search, detail by id and by slug, filters, typed errors (`RAWG_NOT_FOUND`, `RAWG_RATE_LIMITED`, `RAWG_REQUEST_ERROR`).
- **Error system:** `ServiceError`/`DomainError`/`HttpError` with global normalizers and per-module mappers.
- **Common middlewares:** `correlationId` for traceability, `logger` with Pino, `rateLimiter`, `validateSchema` with Zod, global `errorHandler`.
- **Config split:** environment, database, api-keys and rate-limiter in separate files.

## Changed

- Auth and users migrated to the final structure with `controllers/`, `services/`, `schemas/`, `dtos/`, `errors/`.
- Unified validation with Zod across every module.
- Rate limiting wired into routes from the start.

## Files of interest

- `src/common/errors/` — base classes, global normalizers.
- `src/auth/` and `src/users/` — reference business module.
- `src/rawg/` — reference provider.
- `src/common/config/` — domain-split configuration.
