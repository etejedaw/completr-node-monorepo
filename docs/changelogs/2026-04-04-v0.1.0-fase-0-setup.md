# Fase 0 — Setup y arquitectura base (v0.1.0)

**Released:** 2026-04-04

## Summary

Primer release del backend. Levanta toda la infraestructura para que las fases siguientes puedan iterar producto sin pelearse con la fontanería: estructura modular, sistema de errores en 3 capas, validación con Zod, autenticación con JWT, logger con trazabilidad por request y un catálogo de juegos consultable contra RAWG. Sin usuarios reales todavía — el target es dejar la arquitectura sólida.

## Highlights

- Esqueleto del proyecto: TypeScript, Express 5, Sequelize 6, Docker Compose, Postgres + Postgres-test.
- Sistema de errores en 3 capas (`ServiceError` → `DomainError` → `HttpError`) con normalizers globales y mappers por módulo.
- Auth completa con JWT + bcrypt, roles (`user`, `premium`, `moderator`, `admin`) y rate limiting diferenciado.
- Módulos de catálogo: `games`, `platforms`, `genres`, `game-platform`, `game-genre`, `game-shelf`.
- Sistema de puntajes en 3 niveles: `GameScore`/`GameTime` (globales por fuente), `GameShelf` (del usuario), `ListItem` (congelados en listas).
- Provider RAWG con `searchGame`, `getGameById`, `getGameBySlug` y filtros.
- Config dividida en `environment.config.ts`, `database.config.ts`, `api-keys.config.ts`.

## Added

- **Auth (`auth/`):** registro, login, JWT, middleware con verificación de rol, password service con bcrypt.
- **Users (`users/`):** modelo con roles, perfil, gestión de cuenta.
- **Games + catálogo:** `games`, `platforms`, `genres` con sus tablas pivote `game-platform` y `game-genre`. Slugs auto-generados desde el título.
- **Game shelf:** módulo de librería personal con relaciones a Game y Platform.
- **GameScore + GameTime:** tablas separadas para puntajes (Metacritic, OpenCritic, RAWG, Completr) y duraciones (HLTB, RAWG, Completr).
- **DLC support:** `isDlc`, `parentGameId` y self-reference en `Game`.
- **RAWG Provider (`rawg/`):** clase `RawgProvider` con búsqueda, detalle por id y por slug, filtros, errores tipados (`RAWG_NOT_FOUND`, `RAWG_RATE_LIMITED`, `RAWG_REQUEST_ERROR`).
- **Sistema de errores:** `ServiceError`/`DomainError`/`HttpError` con normalizers globales y mappers por módulo.
- **Middlewares comunes:** `correlationId` para trazabilidad, `logger` con Pino, `rateLimiter`, `validateSchema` con Zod, `errorHandler` global.
- **Config split:** environment, database, api-keys y rate-limiter en archivos separados.

## Changed

- Auth y users migrados a la estructura final con `controllers/`, `services/`, `schemas/`, `dtos/`, `errors/`.
- Validación unificada con Zod en todos los módulos.
- Rate limiting integrado en routes desde el inicio.

## Files of interest

- `src/common/errors/` — clases base, normalizers globales.
- `src/auth/` y `src/users/` — referencia de módulo de negocio completo.
- `src/rawg/` — referencia de provider.
- `src/common/config/` — configuración separada por dominio.
