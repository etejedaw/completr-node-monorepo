# Migración a monorepo

**Released:** 2026-09-18

## Summary

El backend y el frontend vivían en dos repositorios separados, con tooling, versiones y documentación duplicados, y cada feature que tocaba ambos lados se coordinaba en dos lugares. Se unifican en un monorepo con npm workspaces: el backend pasa a `apps/api`, el frontend a `apps/web`, y el lockfile, ESLint, Prettier, Husky, la documentación y el changelog quedan en la raíz. Se conserva el historial completo de los dos repos: el del backend sin reescribir (los hashes de los changelogs anteriores siguen siendo válidos) y el del frontend importado bajo `apps/web`.

## Highlights

- `npm run dev` levanta API y web con un solo comando; `npm install` en la raíz instala las dos apps.
- Una sola configuración de ESLint 10 y Prettier para todo el repo.
- Cada app tiene su Dockerfile y su `captain-definition-<app>`, con el contexto de build en la raíz.
- `docs/` y el changelog pasan a cubrir las dos apps.

## Added

- `package.json` raíz con `workspaces: ["apps/*"]`, versión de producto `0.4.0` y scripts `dev`, `dev:api`, `dev:web`, `db`, `db:down`, `build`, `build:api`, `build:web`, `typecheck`, `test`, `migrate`, `migrate:status`, `lint`, `lint:fix` y `format`.
- `eslint.config.mjs` raíz: reglas comunes (`strict`, `stylistic`, `simple-import-sort`, `consistent-type-imports`), reglas con información de tipos para `apps/api` y `angular-eslint` para `apps/web`.
- `captain-definition-api` y `captain-definition-web`.
- `docs/context/frontend.md` con el stack, la estructura y las convenciones del frontend.
- `docs/changelogs/README.md` con el formato de los changelogs.

## Changed

- El backend se mueve a `apps/api` (`src`, `migrations`, `scripts`, `.docker`, `docker-compose.yml`, `tsconfig.json`, `Dockerfile`).
- El frontend se importa en `apps/web`. Su `.prettierrc`, `.nvmrc`, `LICENSE`, `.husky` y la skill `commit` eran idénticos a los del backend y se eliminan; `frontend-design` y `skills-lock.json` pasan a la raíz.
- Un solo `package-lock.json` en la raíz. Las dependencias se resolvieron de nuevo dentro de los rangos de cada `package.json`.
- Paquetes renombrados a `@completr/api` y `@completr/web`. La versión del producto vive solo en el `package.json` raíz; las apps no declaran `version`. Los tres `package.json` son `private`.
- Scripts `migrate*` de `apps/api` apuntan a `../../node_modules/.bin/sequelize-cli`.
- ESLint pasa a la versión 10 en las dos apps.
- TypeScript 6.0 para las dos apps, declarado solo en la raíz. `apps/api` sube desde 5.9.
- En `apps/web`, `no-extraneous-class` admite clases con decorador, `eqeqeq` ignora `== null` y `no-invalid-void-type` se desactiva. Se aplican `consistent-type-imports` y el orden de imports en todo el frontend.
- Prettier 3.9 con una sola configuración; se reformatean los archivos afectados.
- `docker-compose.yml` fija el nombre de proyecto `completr`.
- Dockerfiles reescritos para el contexto de build en la raíz, con `npm ci -w <app>`. Cada imagen copia solo el `package.json` raíz, el lockfile y el de su app. Un solo `.dockerignore` en la raíz. La imagen de la API arranca desde `/usr/app` con `node apps/api/dist/src/app.js`, así que el log de producción sigue en `/usr/app/logs/app.log`.
- `$schema` de `angular.json` y `ngsw-config.json` apuntan al `node_modules` de la raíz.
- Rutas de `docs/` actualizadas a `apps/api/...`; `architecture.md` suma la estructura del repo.
- Skills `db-migration`, `endpoint-doc`, `changelog` y `commit` adaptadas a las rutas y scopes del monorepo.

## Removed

- `lint`, `lint:fix`, `format` y `prepare` de los `package.json` de cada app; el target `lint` de `angular.json`.
- `eslint.config.mjs` de `apps/api`, `eslint.config.js` de `apps/web` y `apps/web/.dockerignore`.

## Migration

- **Deploy:** cada app debe apuntar a su archivo de definición (`./captain-definition-api` o `./captain-definition-web`) y al repositorio unificado. Cada push a `main` reconstruye las dos apps.
- **Tags:** los tags del frontend se renombran a `web/vX.Y.Z`. Desde esta migración, `vX.Y.Z` es la versión del producto completo.
- **Comandos:** todo se ejecuta desde la raíz. Scripts de una app: `npm run <script> -w apps/<app>`. Dependencias: `npm install <pkg> -w apps/<app>`.
- **Variables de entorno:** el `.env` del backend pasa a `apps/api/.env`.
- **Migraciones:** viven en `apps/api/migrations`; se crean con `npm run migrate:create -w apps/api -- <nombre>`.
- **`create:admin` en el contenedor:** se ejecuta con `npm run create:admin -w apps/api -- <email> [password]` desde `/usr/app`.
- **Docker Compose:** el proyecto se llama `completr`, así que los contenedores levantados antes con otro nombre de proyecto no se reutilizan.

## Files of interest

- `package.json` — workspaces y scripts de la raíz.
- `eslint.config.mjs` — configuración única de lint.
- `apps/api/Dockerfile`, `apps/web/Dockerfile`, `.dockerignore` — build de producción.
- `captain-definition-api`, `captain-definition-web` — definición de deploy de cada app.
- `docs/architecture.md`, `docs/context/frontend.md` — estructura del repo y del frontend.
